Hiroshi is a desktop cockpit for multi-agent development. The whole
interface is painted on the GPU through [GPUIX](https://github.com/remorses/gpuix),
the React reconciler over Zed's native GPUI engine. There is no Electron, no
web view and no DOM: the transcript, the composer and the window chrome are
one GPU surface.

## What is in the cockpit

- **The transcript** and the composer, with the model, the reasoning level, the
  access mode and the build mode inline.
- **The conversation sidebar**, grouped by time, with the project, the search
  and the new task action.
- **The thread header**, with run phase and turn count from the engine.
- **The right panel**, with a browser, a terminal, a file browser and a review
  surface.
- **The environment menu**, with the commit and push flow and the branch
  comparison.
- **The command palette**, on the search action, with the conversations, the
  usage and the workspace actions.
- **A settings view** with six sections: general, appearance, providers,
  skills, usage and daemon.

## The window is ours

Hiroshi never shows a native OS titlebar. The chrome spans the whole window
and the titlebar drags it, which means the app moves the window itself. The
[window guide](/window) explains how that works and why the OS modal move
loop is not an option.
